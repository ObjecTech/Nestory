# AI Assistant 架构决策记录 (ADR)

版本：v2（修订版）｜更新日期：2026-10-13｜决策人：项目所有者（用户）

本文档记录 Nestory (Baby Monitor) 引入智能育儿助理 (AI Assistant) 过程中的架构决策，作为 Codex、Gemini、ChatGPT 等 Agent 协作与系统演进的依据。角色分工与 Git 同步规则见 AGENTS.md，本文档不重复。

## 决策状态约定
- **Proposed（提议）**：讨论或 Agent 提出、尚未经用户明确确认。Agent 不得把它当作既定事实去实现。
- **Accepted（已采纳）**：用户明确确认。只有用户可以把状态改为 Accepted。
- **Superseded（已被取代）**：注明取代它的 ADR 编号。

v1 的内容已在仓库中。本版各条在用户确认前保持 Proposed，未改动的部分沿用 v1 的含义。

## 0. 背景与硬件基准
- **部署设备**：NVIDIA Jetson AGX Orin 64GB 开发者套件（系统可用物理内存约 61 GiB，日常空闲约 52 GiB；CUDA 12.6、JetPack 6.x、PyTorch 2.5.0、Transformers 4.57.6）。
- **业务定位**：非医疗、非生命安全级的家庭育儿陪伴应用。核心价值是连续的客观状态记录、时间线整合和个性化育儿建议，而不是实时报警。
- **数据主线**：摄像头自动识别、家长对话记录、陪玩时孩子的反应，都写入事件时间线；AI 从时间线汇总规律并给出指导。

## ADR-001：调度优先级与视觉采样队列

**状态**：Proposed（修订）

### 背景
- 单次视觉推理耗时从数秒到十几秒（v1 记录 2B 模型约 5 至 15 秒；`docs/JETSON_MODELS.md` 中 14.5 秒是合成图的结果，真实画面的数据待补）。
- 家长发起的聊天如果排在视觉推理之后，会出现明显的假死感。
- 视觉观察是周期性抽样，晚几秒或跳过一帧不会造成安全后果。

### 决策
1. **优先级反转**：聊天请求为 P0，视觉周期抽样为 P1。
2. **单槽丢旧留新**：视觉队列容量为 1，新帧覆盖尚未处理的旧帧；服务空闲时只处理最新一帧。
3. **已开始的视觉推理不假定可被抢占**：优先级只在出队时生效。
   - 限制视觉输出长度（配合固定 JSON Schema）和送入图片的分辨率，缩短单次推理。
   - 如果推理服务支持取消生成，聊天到达时可以中止当前视觉请求并丢弃其结果。
   - 不支持取消时，接受最长一次视觉推理时长的等待，并计入 ADR-003 的验收指标。
4. **防饥饿**：设定视觉最长采样间隔。视觉结果过期后，在当前聊天生成结束时先补做一次视觉，再处理后续排队的聊天。
5. **空档要显式记录**：被丢弃或跳过的采样记为"无观察"区间并注明原因（丢帧、模型忙、服务不可用）。状态过滤器不得把空档当作"状态未变化"。
6. **聊天保护**：限制 max_tokens（建议 256 至 512）；使用 SSE 流式输出以压缩首字延迟；结构化抽取和日常记录请求关闭思考模式。
7. **指标记录**：队列等待时间、视觉实际推理耗时、丢帧数、聊天首字延迟。
8. **运行时演进储备**：后续可评估支持连续批处理和多槽位的服务层（如 vLLM、llama.cpp server），让预填充和解码交错调度。

### 后果
- 聊天响应更稳定。
- 视觉观察可能延迟或丢帧，因此不能用作实时报警，这与非医疗定位一致。

## ADR-002：双数据库与统一时间线门面

**状态**：Proposed（修订）

### 背景
- `baby_monitor.db`：摄像头观察（睡眠状态、睡姿、表情、运动幅度等），写入频繁，数据自动清理。
- `assistant.db`：聊天会话、家长记录的护理事件（喂奶、尿布、体温、用药等）、偏好配置。
- Assistant 需要同时看到两类数据，才能回答"宝宝今天睡得好吗"这类综合问题。

### 决策
1. **保持两个独立的 SQLite 文件**。理由是两类数据的生命周期和删除语义不同（视觉观察自动清理；家长删除对话或记录不应影响视觉数据），便于分别备份、删除和隔离故障。
2. **写入边界**：视觉管线只写 `baby_monitor.db`；Assistant 与护理记录只写 `assistant.db`。所有写入经主应用完成，模型 worker 不直接访问数据库。
3. **统一读取门面**：在后端数据访问层提供统一的时间线查询。使用两个只读连接分别读取再合并，不依赖跨库视图（SQLite 的视图跨 ATTACH 的库只在当前连接内有效）。如果使用 ATTACH，必须以只读方式并在同一连接内查询。
   ```python
   def get_unified_timeline(start_ts: float, end_ts: float, baby_id: str = "default") -> list[TimelineEvent]:
       """合并视觉事件与手动护理事件，按时间正序返回。"""
   ```
4. **TimelineEvent 字段**：`event_id`、`ts_start_utc`、`ts_end_utc`（可空）、`type`、`source`（vision / manual / chat）、`confidence`（视觉事件有，手动事件为空）、`recorder`（视觉事件为 system，手动事件为记录人）、`payload`。
5. **不静默合并**：视觉判断的"睡着"和家长说的"睡了"并存，保留来源，门面不自动去重。呈现和回答时要说明来源。需要去重时另立 ADR。
6. **Assistant 接入**：Context Builder 注入近 24 小时事件摘要（按来源标注）；工具集提供 `query_timeline(range, event_type)`。
7. **实验性字段**：如果 `baby_monitor.db` 中存在心率、呼吸等估计值，必须标注为实验性、未经验证；默认不进入 Assistant 上下文，界面上标明未验证，不得据此做医疗解读。（注：经核对代码库现状，当前 `baby_monitor.db` 并未实现心率呼吸等体征估计字段；若未来实验性引入，必须严格遵守本条）。
8. 记录与对话的独立性见 ADR-007。

## ADR-003：模型路线与目标架构

**状态**：Proposed（修订，取代 v1 的 ADR-003）

### 事实澄清
内存容量不是瓶颈（空闲约 52 GiB，两个小模型都放得下）。但 GPU 算力和内存带宽是共享资源，两个实例同时推理仍然会互相拖慢。因此"内存够用"不等于"无抢占"。

### 目标架构
一个模型服务实例 + 视觉客户端 + 助手客户端 + 各自独立的提示词与输出格式 + 两个数据库 + 可拆分的服务地址配置。

```
Web 前端 (Port 8080) ──> 后端 API (/api/assistant/chat) ──> 助手客户端 ─┐
                                                                       ├─> 模型服务（Phase 1：Qwen3-VL-2B，Phase 2 候选：Qwen3.5-4B）
摄像头采样 ────────────────────────────────────────────────> 视觉客户端 ──┘
```

- 配置项 `BMON_VLM_SERVICE_URL` 与 `BMON_ASSISTANT_SERVICE_URL`，默认指向同一地址（回环地址 8010），并同步更新 `.env.example`。
- 前端始终只访问 `/api/assistant/chat`，由后端按配置路由，前端不感知模型拓扑。
- 两个客户端各自拥有提示词、输入输出格式和调用参数（例如视觉与抽取关闭思考模式）。

### 分阶段路线
- **Phase 1（当前基线）**：沿用 Qwen3-VL-2B-Instruct，同一服务支撑视觉抽样和 Assistant 聊天。
  - 验收重点：端到端链路、ADR-001 的优先级与丢旧队列、前端流式输出、会话管理、SQLite、跨会话检索。
  - 2B 在记录抽取上可靠性偏低，抽取准确率只作为基线记录，不作为架构是否成立的判据。
- **Phase 2（候选：Qwen3.5-4B，原生多模态，可同时承担视觉与对话）**。进入条件是冒烟测试通过：
  - 在独立环境中验证，不升级现有 `.venv-models`，避免破坏已验证的视觉链路。
  - 能在 Jetson 上加载；图像输入能输出符合现有 Schema 的 JSON；文本对话和结构化抽取正常；思考模式可按请求关闭；连续运行无异常。
  - 如果现有 PyTorch、Transformers 版本无法加载，评估其他运行时，或退回 Qwen3-VL-4B（与现有 2B 同系列）。
- **拆分触发条件**：在并发压力测试下，聊天首字延迟或视觉最长间隔超过阈值时，把 `BMON_ASSISTANT_SERVICE_URL` 指向第二个模型实例。客户端和前端 API 契约不变。

### 验收指标
下面是建议初值，以 Phase 1 实测校准后再正式确定：

| 指标 | 建议初值 |
| :--- | :--- |
| 聊天首字延迟（TTFT） | 不超过 5 秒（视觉推理并发时） |
| 视觉最长采样间隔 | 不超过 120 秒 |
| 视觉单次推理耗时 | 以真实画面实测为准，不超过请求超时的一半 |
| 连续运行 | 24 小时无崩溃、无明显内存增长 |
| 内存余量 | 不低于 10 GiB |

### 回归测试集（与模型无关）
放在 `tests/` 下：约五十句带相对时间的家长话术，加上 ADR-007 的完整流程用例。更换模型时直接复用，用来判断有没有退化。

### 报告措辞
官方公开的通用基准成绩不得写成婴幼儿识别准确率。需要对外说明识别效果时，只使用项目自建小测试集的实测数据。

## ADR-004：决策治理与跨 Agent 协作

**状态**：Proposed（修订）

### 背景
不同 Agent、不同会话之间不共享记忆。关键决策如果只留在聊天里，会被遗忘或被重复推翻；但如果允许 Agent 把聊天内容直接写成"权威规范"，猜测也会被固化。

### 决策
1. **代码库文档是单一事实源**：硬件状态、架构决策、接口契约记录在 `AGENTS.md` 和 `docs/` 中；未落盘的聊天不作为技术依据。
2. **前置阅读**：任何 Agent 接手任务前，先读 `AGENTS.md` 与本文档。
3. **决策治理**：
   - Agent 可以把讨论中的建议写成 Proposed 条目并提交，但只有用户明确确认后才能改为 Accepted。
   - 更换模型、改变服务拓扑、改变数据边界、新增对外联网，必须先经用户批准。
   - ADR 与聊天内容冲突时，以已 Accepted 的 ADR 为准，直到用户明确更新。
4. **同步**：按 `AGENTS.md` 的 Git 与同步规则执行（包括 `bash scripts/sync-jetson.sh`）。文档同步不触发服务重启，不自动暂存无关文件。
5. **角色分工**以 `AGENTS.md` 为准，本文档不重复。

## ADR-005：时钟、时间戳与离线运行

**状态**：Proposed（新增）

### 背景
- 设备需要携带并在断网时使用。
- `docs/JETSON_MODELS.md` 记录过重启后时间回退（硬件时钟 1970 年，系统日期 2024-11-28）。时间错误会直接破坏时间线和规律分析。
- v1 中"NTP 已同步"只是当时的状态，不是长期保证。

### 决策
1. **时间戳统一存 UTC**；展示以及"今天"的边界按设备配置的时区计算（默认 Asia/Shanghai）。
2. **时钟可信度检查**：启动时和运行中定期检查（例如与已知时间下限比较，或检查最近一次成功校时）。不可信时，新事件带 `clock_untrusted` 标记。
3. **不可信期间的处理**：带该标记的事件不参与规律统计；Assistant 解析"刚才""半小时前"只用可信时钟，时钟不可信时请家长确认具体时间，并提示"设备时间未校准"。
4. **硬件方案**：为断网期间保持时间，需要带电池的 RTC（具体方案待定）；联网后通过 NTP 校时。校时后新事件恢复正常，此前已标记的事件保持标记。

## ADR-006：联网与数据边界

**状态**：Proposed（新增）

### 背景
演示时设备联网；日常使用和携带时可能断网。项目的核心卖点之一是数据留在本地。

### 决策
1. **离线优先**：摄像头识别、对话记录、规律统计、本地内容库在断网时都可用。联网只做增强：内容推荐补充、育儿知识检索、NTP 校时。
2. **数据边界**：孩子的记录、照片、视频、对话内容不上传。对外请求只包含通用查询词（例如"6 个月宝宝睡眠规律"），不含孩子身份和记录。
3. **默认关闭，由用户开启**；每次对外查询对家长可见、可审计。
4. **工具隔离**：联网搜索的结果视为不可信文本。处理搜索结果的那一轮不得触发写库或删库类工具。
5. **来源与降级**：育儿知识限定来源白名单并附出处；获取的内容缓存到本地；断网时静默退回本地内容，不报错。
6. **音乐版权**：不内置受版权保护的音乐；内容库使用公版、自制或用户自行导入的内容。
7. **暴露面不变**：应用仍只监听回环地址，经 TLS 反向代理访问（沿用 `README.md` 与 `SECURITY.md`）。出站联网不等于开放入站。

## ADR-007：对话记录的抽取、确认与规律分析

**状态**：Proposed（新增）

### 决策
1. **模型只做结构化抽取**：输出固定 Schema（类型、数量与单位、时间、备注），不生成 SQL。
2. **入库前确认**：前端展示确认卡（例如"喂奶 150ml，10:30"），家长确认后才写入 `assistant.db`。
3. **相对时间由代码换算**：按可信时钟（ADR-005）把"刚才""半小时前"换算成具体时间，不让模型猜。
4. **查询走预定义函数**：如今日喂奶汇总、`query_timeline`，模型负责用自然语言说明结果。
5. **规律统计由代码计算**（喂奶间隔中位数、入睡时段等），模型只做解读。数据不足时明说不足，不编造。
6. **记录与对话相互独立（不变量）**：
   - 删除会话不删除由它产生的护理记录；护理记录可以单独删除。
   - 记录通过可空的 `source_message_id` 关联消息，消息删除后置空。
7. **安全边界**：非医疗，不做诊断；发烧、呼吸异常等红旗症状固定提示就医；育儿建议注明来源（ADR-006）。
8. **抽取与日常记录请求关闭思考模式**。

### 验收用例
新建对话 A，告诉 AI "宝宝喝了 150ml 奶"，确认后入库 → 新建对话 B，查询当天喂奶情况，得到 150ml → 回到对话 A，历史仍可查看 → 删除对话 A，对话消失，喂奶记录仍保留 → 单独删除该记录后，再查询不再返回它。
