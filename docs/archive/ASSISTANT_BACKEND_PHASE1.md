## Implemented interfaces

All 13 frozen method/path combinations are implemented and exercised over real
loopback HTTP with isolated SQLite and a synthetic model:

| Method | Path after `/api/assistant` | Implemented |
|---|---|---|
| GET | `/conversations` | scope-filtered, bounded keyset paging |
| POST | `/conversations` | empty conversation, explicit scope, default timezone |
| PATCH | `/conversations/{id}` | manual title, optional optimistic version |
| DELETE | `/conversations/{id}` | delete messages/turns/proposals, preserve events |
| GET | `/conversations/{id}/messages` | chronological latest page and older-page cursors |
| POST | `/conversations/{id}/messages` | HTTP 202, client-ID deduplication and explicit failed retry |
| GET | `/conversations/{id}/messages/{user_message_id}` | durable queued/running/completed/failed poll envelope |
| POST | `/conversations/{id}/messages/{user_message_id}/record-actions/{action_id}/confirm` | confirm/dismiss, expiry and repeat protection |
| GET | `/care-events` | scope/time/type filters and keyset paging |
| POST | `/care-events` | explicit form event, client-event-ID deduplication |
| PATCH | `/care-events/{id}` | expected-version correction with audit revision |
| DELETE | `/care-events/{id}` | expected-version soft deletion with audit revision |
| GET | `/sleep-summary` | clipped manual interval union; no unverified camera total |

ID routes require query `scope`, just as in the confirmed contract. Writes require
existing session, exact Origin and X-CSRF-Token. Errors use the nested v1 envelope
without the visual serializer altering error objects. The existing network/Host/
Tailscale-owner/access-disable checks remain in force.

No frontend files were edited. Gemini can use the contract response shapes
without introducing alternative paths or streaming semantics. Accepted POST
responses are snapshots taken before dispatch, so the first 202 actually reports
queued state even if the mock model subsequently completes immediately.

## Persistence and transactions

- `${BMON_DATA_DIR}/assistant.db`, WAL, foreign keys, synchronous FULL, private
  file permissions, short locked transactions. A process-exclusive file lock prevents
  a second controller from misclassifying another live worker’s turns as interrupted.
  The visual database is untouched.
- Migration 1 implements the contract's eight-table candidate SQL and scope
  triggers; migrations 2–4 add internal clarification linkage fields and their
  scope/conversation constraints. These do not change the HTTP contract.
- At startup queued/running turns become failed with `service_restarted` and need
  explicit retry. Completed replies/events are not regenerated.
- Event creation/correction/deletion is committed with structured revisions.
  Successful care acknowledgements are generated by Python after commit.
  Model-written persistence claims are discarded.
- All turn completion writes occur in one transaction after checking the live
  turn, conversation and authorization. Deletion winning a race prevents late
  message/event writes. Event source links become null when chat is deleted;
  revisions retain structured care data, not duplicated deleted chat bodies.
- Manual event retry and turn retry are idempotent. Chat clarification linked by
  `record_action_id` resolves the original proposal; partial clarification cards
  share the same original event-creation key, preventing a second event.
- Demo and Real remain separate from visual infant/adult modes. Scope cannot be
  changed on an existing conversation or event.

## Extraction and facts

The model returns structured proposals, not executable SQL. Backend checks enums,
field types, current-message evidence, supported dates/clocks, actual consumed
milk amount, diaper unknown, sleep endpoints, future/negated statements,
corrections and bounded action count. Duplicate model actions are rejected.
Incomplete/ambiguous information becomes a confirmation card instead of an
invented timestamp or quantity. Explicit chat corrections/deletions require
confirmation and event version checks.

This is a conservative parser. Unsupported or unclear language should prompt
confirmation; comprehensive Mandarin extraction quality has **not** been measured
against real Qwen. Unit tests validate the backend's behavior with controlled
model proposals, not the model's linguistic accuracy.

Facts use parameterized allowlisted Python/SQLite queries. Manual sleep spans
are clipped and unioned, including calendar/DST boundaries. Camera duration is
always null with continuity-unverified warnings; open intervals never become
trusted sleep totals. Real visual evidence is infant-mode-only, bounded and read
through read-only connections. Demo does not retrieve live visual history.
Numeric answers are rendered from Python facts, not model arithmetic. Evidence
sent for model explanation is compacted and explicitly marked when truncated.

## Shared Qwen implementation and guards

`model_server.py` adds loopback `/chat` using the existing Engine/model/processor.
Existing `/analyze` result fields and Infant/Adult prompts are retained.
Both call paths hold one scheduler slot before processor use and GPU input
transfer, through generate, CUDA synchronization, decode and tensor cleanup.
No second model is created.

- Default waiting capacities: 1 vision, 2 chat, plus 1 running job.
- Vision first; after two consecutive vision jobs a waiting chat can progress
  only when the conservative next-vision budget allows it.
- Vision observer sends a capped minimum-interval budget hint; no monitoring
  interval configuration is changed.
- Chat queue deadline 30s; vision queue deadline 10s; input <=2048 tokens, output
  <=256 tokens, at most six completed recent turns plus the current message.
- Chat uses `max_time=8.0` and rejects an over-budget result. This is a **soft**
  generation guard: prefill/GPU kernels are not immediately preemptible.
- Model HTTP handler concurrency is bounded at 8; Assistant HTTP at 16 and
  accepted Assistant turns at 4 with one background business worker.
- `/health` does not own the GPU and includes aggregate scheduler metrics.
- Saturated/unknown visual capacity returns `vision_capacity_reserved`; it never
  silently slows the monitoring interval or starts overlapping generation.

`BMON_ASSISTANT_ENABLED` defaults false. It must be explicitly provided to both
application and model processes during future maintenance validation.
`scripts/run-model.sh` does not automatically source `.env`; provide the environment
when launching that process. `BMON_ASSISTANT_ALLOW_UNPROFILED_CHAT` defaults false
and is for an isolated model test only, never a workaround on the live monitor.

Real Qwen multi-turn Chinese replies, structured-output reliability, p50/p95/max
latency, peak GPU memory, camera cadence and real priority/fairness remain
**unverified hardware acceptance**. No Jetson model/service was restarted or used
for inference experiments in this phase.

```bash

python3 -m py_compile server.py model_server.py baby_monitor/assistant_*.py baby_monitor/inference_scheduler.py scripts/run-assistant-dev.py
```

Results: **159 Python tests: 158 passed, 1 existing optional pinyin test skipped**;
**1 Node test passed**. Of the Python tests, **66 are new Assistant tests**, with
no hardware/model weights/cloud API needed. The frozen contract was also compared
byte-for-byte against `git show 7cf02ac:docs/ASSISTANT_API_CONTRACT.md`.

Coverage includes:

- A/B history, switching, context separation, paging, rename, restart persistence;
- queued/running deletion races, event preservation and source-link cleanup;
- concurrent client-ID duplicates, replay/conflicts, restart recovery and retry;
- feeding/diaper/nap/activity proposals, ambiguity, planned/negated/prepared events;
- confirmation/dismissal/expiry, clarification aliases, stale correction versions;
- transactional rollback injected at revision creation: no event or false reply;
- Demo/Real filters and DB scope triggers; legacy/adult visual exclusion;
- overlapping manual sleep union, window clipping, DST and untrusted open intervals;
- all 13 HTTP routes, session/CSRF/Origin/Host/access failures, malformed/large bodies;
- synthetic Engine/model transfer ownership, priority/fairness, queue bounds,
  expiration, failure cleanup, context/output budgets, responsive health during generation;
- real loopback transport with synthetic model output, malformed/large/error responses;
- isolated development launcher with actual application initialization and same-origin API;
- Assistant initialization failure/disabled state preserving visual component startup.

No automated failures remain at this checkpoint. Passing these tests is not a
claim that actual Qwen accuracy, physical camera/audio, or Jetson GPU scheduling
has passed acceptance.

## Gemini local integration

From this backend worktree:

```bash
python3 scripts/run-assistant-dev.py --port 18881 --static-dir /path/to/gemini-worktree/static
```

The launcher asks you to choose a development password (no default password),
uses username `assistant-dev` unless `--username` is supplied, binds only
127.0.0.1, and uses ignored `data/assistant-dev/` for both development databases.
It does not load `.env`, open physical camera/audio devices, start the model
worker, or call the real Qwen service. Replies explicitly say they are synthetic.
Its mock extraction is only a UI fixture, not model-quality evidence.

Open `http://127.0.0.1:18881/`, sign in, then use same-origin fetch with session
cookies and CSRF token. Existing visual/demo interfaces can remain available
while the Assistant frontend is developed from Gemini's own static directory.
Keep the mock development archive separate from real care records.

Use `status`, not HTTP 200 alone, to decide whether a turn completed. Show record
cards from `record_actions`; keep polling with the accepted ID, never auto-create
a replacement conversation after 404. On 409 reload versioned event state. Do
not total manual plus camera sleep. Use the stable v1 scope field in every ID URL.
